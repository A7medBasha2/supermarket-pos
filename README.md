# Supermarket POS

نظام إدارة سوبر ماركت (Flutter + Supabase) من **تطبيقين**:

| التطبيق | ملف الدخول | الاستخدام |
|---|---|---|
| **تطبيق صاحب المحل** (`owner-app.apk`) | `lib/main.dart` | مخزون، كاشير (POS)، تقارير، استقبال طلبات العملاء. الإدارة بتشتغل **أوفلاين** وبتتزامن لما النت يرجع. |
| **تطبيق العملاء** (`customer-app.apk`) | `lib/customer/customer_main.dart` | العميل يدخل بكود المحل، يتصفح، يطلب، ويحدد موقعه على الخريطة. **أونلاين**. |

كل سوبر ماركت له حساب واشتراك شهري، وبيانات كل محل معزولة عن التاني.

## الإعداد من الموبايل (بدون كمبيوتر)

### 1) قاعدة البيانات (Supabase)
1. مشروع جديد مجاني على supabase.com.
2. **SQL Editor ← New query**: شغّل بالترتيب (كل ملف كامل، وآمن لو اتشغّل مرتين):
   1. `supabase/schema.sql`
   2. `supabase/002_orders_and_customers.sql`
   3. `supabase/003_fulfillment_delivery_or_pickup.sql` (العميل يختار توصيل أو استلام)
   4. `supabase/004_admin_subscription_tools.sql` (أدوات تجديد وإيقاف الاشتراكات لك كأدمن)

   لو شغّلت 003 قبل تحديث تطبيق العملاء مفيش مشكلة: نسخة `place_order` القديمة بتفضل شغالة (توصيل فقط).
3. **Authentication ← Sign In / Providers**: خلّي Email شغال و**عطّل Confirm email** (للتجربة)، و**عطّل Anonymous sign-ins** (التطبيق مش محتاجها).
4. **Project Settings ← API**: انسخ **Project URL** و **anon / publishable key**.

### 2) ربط التطبيق (GitHub Secrets)
**Settings ← Secrets and variables ← Actions ← New repository secret**:

| الاسم | القيمة |
|---|---|
| `SUPABASE_URL` | Project URL |
| `SUPABASE_ANON_KEY` | anon / publishable key |

### 3) بناء ملفات APK
1. **Actions ← Build Android APKs ← Run workflow** (بيشتغل لوحده مع كل push).
2. بعد ما يخلص (10-20 دقيقة) نزّل الـ Artifact `supermarket-apks`: جواه `owner-app.apk` و `customer-app.apk`.
3. **أول مرة فقط** امسح النسخة القديمة من الموبايل، وبعد ما تضيف مفتاح التوقيع (الخطوة اللي بعدها) كل تحديث بعد كده بيتثبّت فوق القديم من غير مسح ولا فقد بيانات.

### 4) مفتاح التوقيع الثابت (عشان التحديث يتثبّت فوق النسخة القديمة)
أندرويد بيرفض تحديث تطبيق لو الملف الجديد متوقّع بمفتاح مختلف. من غير مفتاح ثابت كل بناء على GitHub بيتوقّع بمفتاح مؤقت جديد. المفتاح الثابت بيتحط **مرة واحدة** كـ Secrets، وكل البنايات بعد كده (تطبيق المحل وتطبيق العملاء) بتتوقّع بيه.

أضف 4 Secrets في **Settings ← Secrets and variables ← Actions ← New repository secret**:

| الاسم | القيمة |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | محتوى ملف `keystore.b64` (نص طويل، انسخه كله بالظبط) |
| `ANDROID_KEYSTORE_PASSWORD` | كلمة مرور المفتاح |
| `ANDROID_KEY_ALIAS` | `supermarket` |
| `ANDROID_KEY_PASSWORD` | نفس كلمة المرور |

- في لوج البناء (خطوة **Print APK signing certificate**) بتظهر بصمة الشهادة SHA-256. **لازم تبقى نفسها في كل بناء.**
- رقم إصدار التطبيق بيزيد تلقائياً مع كل بناء (`--build-number`).
- **احتفظ بنسخة احتياطية من ملف المفتاح وكلمة المرور في مكان آمن.** GitHub مش بيسمح تقرأ الـ Secrets بعد حفظها، ولو المفتاح ضاع لازم كل المستخدمين يمسحوا التطبيق ويثبّتوه من جديد. وماتحطوش في الريبو أبداً.
- لو الـ Secrets ناقصة البناء بيكمّل بمفتاح مؤقت مع تحذير، والتطبيق مش هيتحدّث فوق القديم.

## تجربة السيناريو كامل
1. **تطبيق صاحب المحل**: حساب جديد (بيانات المحل) ← أضف منتجات بـ **كمية أكبر من صفر** (العميل مش بيقدر يطلب منتج مخزونه صفر) ← **الإعدادات**: انسخ **كود المحل**، وظبط رسوم التوصيل.
2. **تطبيق العملاء** (على موبايل تاني): اكتب كود المحل ← حساب جديد بإيميل وكلمة مرور ← أضف للسلة ← **إضافة عنوان على الخريطة** ← تأكيد الطلب.
3. عند صاحب المحل: تنبيه صوتي + اهتزاز فوري (والتطبيق مفتوح) وبادج على تبويب **الطلبات** ← قبول ← خرج للتوصيل ← تم التسليم. والعميل بيشوف الحالة في **طلباتي**.

## الموقع (GPS) ودقته
- GPS مفيش منه دقة 100%: في المكان المفتوح غالباً 3-10 متر، وجوه العمارات ممكن 30 متر أو أكتر.
- التطبيق بياخد أدق قراءة خلال ~12 ثانية، وبيعرض دائرة الدقة، والعميل **يأكد الدبوس بنفسه** على الخريطة (ويحرّكه لو GPS غلط).
- الإحداثيات بتتخزن زي ما هي (من غير تخمين عنوان) مع العنوان والعلامة المميزة، وبتتفتح في **خرائط جوجل** عند صاحب المحل بنفس الإحداثيات.
- الخريطة OpenStreetMap مجانية. استخدامها الخفيف مسموح، ولو الاستخدام كبر لازم نبدّل لمزوّد خرائط تاني.

## الاشتراكات (من عندك كأدمن)
كل محل جديد بياخد **تجربة 14 يوم**. بعد تشغيل `004_admin_subscription_tools.sql` تدير كل حاجة من **SQL Editor** بالكود الخاص بالمحل (بتلاقيه في إعدادات تطبيق المحل):

```sql
-- كل المحلات وحالتها (الأقرب للانتهاء الأول): نشط / سماح / منتهي / موقوف
select * from public.admin_stores_overview();

-- جدّد اشتراك محل شهر (لو لسه شغال بيزوّد على تاريخ الانتهاء، ولو منتهي بيبدأ من النهارده)
select public.admin_renew_subscription('a1b2c3d4', 1);

-- أوقف محل أو رجّعه
select public.admin_set_subscription_status('a1b2c3d4', 'suspended');
select public.admin_set_subscription_status('a1b2c3d4', 'active');
```

الدوال دي ممنوعة على التطبيقات: بتشتغل من SQL Editor بس.

**تحذيرات قبل الانتهاء:** تطبيق المحل بيعرض شريط برتقالي قبل الانتهاء بـ 5 أيام وأثناء الـ 3 أيام سماح. والتجديد بيظهر في التطبيق تلقائياً في أول مزامنة (خلال ~45 ثانية لو فيه نت).

لما الاشتراك ينتهي (بعد 3 أيام سماح):
- السيرفر بيرفض أي كتابة (بيع، تعديل منتجات، تغيير حالة الطلبات).
- تطبيق صاحب المحل بيتحول للقراءة فقط.
- **تطبيق العملاء بيقف:** الكتالوج بيرجع "المتجر غير متاح" ومفيش طلبات جديدة.
